# AccessAI v4.1 · 可追溯的无障碍出行助手

面向轮椅使用者的 Web 应用原型，围绕表达通行需求、查询设施、规划路径、分步指引和受阻处理展开。v4.1 针对第九届传智杯 AI WEB 网页开发挑战赛，加入模型工具调用和带来源的资料检索。当前已接入**阿里云百炼北京地域 `qwen-plus`**，完成真实 API 与浏览器流程联调；应用仍为本地原型，路线使用虚构数据，不用于现实导航。

## v4 新增与验证边界

- **出行助手 `dist/assistant.html`：** 自然语言输入、明确的模拟起点与通行条件、阶段进度、取消与重试、来源片段和工具执行记录。对话只在本次页面内存中保留。
- **模型工作流：** 服务端通过 OpenAI 兼容的 Chat Completions / Function Calling 接口调用模型，最多 3 轮请求。模型理解需求、选择工具并提取参数，调用 `plan_accessible_route` 取得确定性路线，或调用 `search_station_knowledge` 检索资料。成功路线正文中的距离、净宽、设施和步骤由工具结果确定性生成；站点问答由模型依据检索片段回答。模型不能自由生成道路连接或路线数值。
- **小型 RAG：** 将已有 6 站官方资料拆为带来源的片段，使用站名/城市约束和中文二元字符词法匹配检索；不是向量数据库，也不宣称实时联网搜索。
- **真实 AI 与规则演示：** 只有明确配置服务地址、模型名和密钥才可请求真实模型；未配置不会偷偷切换为假 AI。独立的“规则演示（非 AI）”用于离线数据和交互验收，不证明模型质量。
- **统一路径交接：** 助手生成的规划条件可送到图上规划页重新计算。用户必须确认模拟起点，再查看地标、逐段指引、本地中文朗读和本机反馈。
- **手机与无障碍：** 起点、目的地和条件优先于地图；保留键盘操作、步骤焦点与状态播报。

原有静态资料和模拟路线仍可离线打开。**完整助手需要运行本机 Node 服务**；模型配置成功只表示配置完整，不表示服务商可用、账户有额度或模型质量达标。服务器不记录对话正文，不上传设备 GPS；使用真实 AI 时，用户提交的文字、所选模拟条件、最近对话和工具资料会发送给配置的模型服务商。

## 快速运行完整版本

要求 Node.js **20.12 或更新版本**（使用原生 `fetch`、`AbortSignal.any` 和 `node:test`）。项目没有第三方运行时依赖，不需要安装 npm 包。

在解压或克隆后包含 `package.json` 的项目根目录执行：

```powershell
node server.cjs
```

打开 [出行助手](http://127.0.0.1:4173/assistant.html) 或 [首页](http://127.0.0.1:4173)。也可双击 `启动完整演示.cmd`，在终端保持服务运行；`Ctrl+C` 停止。没有模型密钥时，选择明确标记的规则演示。

配置真实模型时，复制 `.env.example` 为 `.env`，填写服务商提供的 **API 基础地址、支持工具调用的模型名及密钥**，再重启服务：

```text
AI_BASE_URL=https://YOUR_WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
AI_MODEL=qwen-plus
AI_API_KEY=YOUR_PRIVATE_API_KEY
```

`YOUR_WORKSPACE_ID` 和 `YOUR_PRIVATE_API_KEY` 是占位符，需换为本人北京地域业务空间对应的信息；也可直接复制百炼控制台提供的 OpenAI 兼容 Base URL。基础地址应使追加 `/chat/completions` 后得到服务商的真实接口。应用启动时读取配置，修改 `.env` 后需重启服务。`qwen-plus` 默认非思考模式，支持当前工具调用协议；这里未使用额外向量数据库或付费搜索接口。[百炼接口文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[模型能力与价格](https://help.aliyun.com/zh/model-studio/qwen-plus)。

优先使用 HTTPS；仅为本机测试允许回环 HTTP。不要把密钥写进前端、演示视频或代码仓库。`.env` 已列入忽略规则，交付只含 `.env.example`。2026-11-17 已完成真实模型调用，测试请求使用合成演示需求，结果与边界见 `docs/competition/verification.json` 及 `docs/competition/evidence/`。

## 架构与文件

```text
浏览器 assistant.html
  → POST /api/assistant（同源；SSE 阶段进度与最终结果）
  → Node server.cjs（校验、限流、超时、取消、静态资源）
  → lib/assistant.cjs（模型请求、受限工具调用、路线事实格式化）
      → lib/knowledge.cjs（官方资料分块与词法检索）
      → dist/route-network.js（现有确定性 Dijkstra 路网）
  → 资料来源 / 路线卡片
  → navigate.html（重新计算、确认起点、逐段查看）
```

`GET /api/health` 只提供配置状态和模型名，不测试模型连通性，不返回密钥。服务端只执行登记工具，禁止由模型提供任意网络地址。SSE 展示实际执行阶段，最终回答整体返回；没有宣称逐 token 输出或展示模型内部思维。

现有 `.openai/hosting.json` 是早期静态部署配置，**不能直接承载 v4 的 Node AI 服务**。若后续上线，需要支持 Node 的服务环境或单独移植服务端运行时，并为 API 配置 HTTPS、限额和必要的访问控制。当前版本没有部署。

## 原有模拟规划与真实资料

v3 新增 `dist/navigate.html`：点击“使用当前位置”可由浏览器申请定位；由于未接入真实人行路网，成功后仍明确提示覆盖不足。另可在虚构街区的人行路径中间选择起点，确认后动态计算路线，过滤台阶、未知路径、宽度不足和停用路段。真实位置不会进入虚构路网。详见 [NAVIGATION-NOTES.md](./NAVIGATION-NOTES.md)。

项目包含两类独立内容：

- **模拟路线体验：** 从虚构的云桥地铁站前往商场、医院或公园，提供 3 个目的地、4 条路线和 6 种模拟状态。该部分的地点、图片、距离、耗时、开放时间与核验记录均为合成样例，不用于真实导航。
- **真实站点资料：** 展示深圳和香港共 6 个真实车站的官方设施资料摘要，支持城市筛选、查阅来源及复制摘要。这些是已保存的资料，不是实时设备状态，也没有生成真实站点的完整路线。

原有领域测试包含 24 项。v4 新增 AI 接口、工具约束、检索和浏览器验收，最新执行结果以 `docs/competition/verification.json`、公开证据及实际执行输出为准。定位检查使用模拟结果，没有获取测试人员真实位置。`tests/ai.test.cjs` 与既有浏览器回归使用本地 mock provider；真实模型验证单独标注服务商、模型、时间和用量。两类测试都不代表真实世界路线已经核验。

页面不自动申请定位。新规划页仅在用户主动点击后请求浏览器定位；模拟行程的位置由选点或到达确认更新。真实资料的来源、读取方式与适用范围见 [REAL-DATA-SOURCES.md](./REAL-DATA-SOURCES.md)。

## 离线打开原有页面

前端使用原生 HTML、CSS、JavaScript 和本地 SVG，无需安装 npm 依赖或构建。

可以直接用浏览器打开 `dist/index.html`，Windows 下也可双击 `打开演示.cmd`。核心页面、插图及已保存的真实站点资料均在本地；访问官方原文链接需要联网。浏览器对 `file://` 下的存储、剪贴板和语音能力支持可能不同：复制受限时提供可手动选取的摘要，朗读不可用时保留图文指引。

也可以在项目目录执行：

```powershell
node server.cjs
```

然后打开 [http://127.0.0.1:4173](http://127.0.0.1:4173)。在终端按 `Ctrl+C` 停止服务。运行服务及领域测试需要安装支持 `node --test` 的 Node.js。

服务默认使用 `4173` 端口，**只绑定 `127.0.0.1`**，不会自动向局域网开放。手机无法通过电脑的局域网 IP 访问这个默认服务；可使用桌面浏览器的手机尺寸预览。端口被占用时，在 PowerShell 中指定其他端口：

```powershell
$env:PORT = '4174'
node server.cjs
```

## 功能与体验流程

- **从当前位置开始：** 主页点击“从当前位置出发”，由用户主动授权定位；成功后显示精度与当前路网覆盖情况。未接入真实路径时不能开始实际导航。
- **任意起点规划：** 在虚构地图的人行通道中间点选起点，确认投影位置，动态计算去往商场、医院或公园的路径。修改净宽需求、设备停运或施工条件后重新计算；手机可横向滑动地图，也可使用地标选择框。
- **找目的地：** 从主页选择商场、医院或公园，或搜索演示地点和真实站名。
- **看路线：** 手动选择已知位置，查看所经电梯、出口、目的地入口和剩余步骤。
- **按步骤前进：** 查看楼层、地标示意图和动作说明，确认到达后继续；已完成的步骤可以回看。
- **处理受阻：** 模拟电梯停运、商场入口关闭或公园通道积水，查看同一目的地的替代路线或协助提示。
- **查真实资料：** 单独浏览 6 个真实站点，按深圳或香港筛选，查看出口设施、来源、读取方式、检索日期及待确认事项；复制摘要时保留来源与状态说明。
- **保存与反馈：** 收藏模拟路线，在本地记录、查看、删除及导出问题反馈。
- **调整阅读：** 使用大字模式，或在设备支持本地中文语音时朗读当前步骤。

收藏、反馈及阅读设置保存在当前浏览器。反馈不代表已向地铁、商场、医院或公园工作人员提交信息。清理本站浏览器数据会清除相应记录；存储受限时，页面会说明记录只在本次打开期间有效。

## 3 个目的地与 4 条路线

| 路线 | 目的地入口 | 经过设施与出口 | 从站台出发的全程样例值 |
| --- | --- | --- | --- |
| A | 星河商场南入口 | E1 → 站厅 → E2 → A 出口 | 380 米 / 8 分钟 |
| B | 星河商场东入口 | E1 → 站厅 → E3 → C 出口 | 560 米 / 12 分钟 |
| H | 云桥社区医院门诊入口 | E1 → 站厅 → E3 → C 出口 | 680 米 / 14 分钟 |
| P | 云桥公园东入口 | E1 → 站厅 → E2 → A 出口 | 460 米 / 10 分钟 |

路线编号与地铁出口编号不同：**路线 B、H 经过 C 出口，路线 P 经过 A 出口到公园东入口。** 医院行程止于门诊入口，后续楼层与通道需向服务台确认；公园行程止于东入口，未纳入园内游览路线。

| 电梯 | 连接位置 | 从站台或站厅出发时的相关路线 |
| --- | --- | --- |
| E1 | B2 站台 ↔ B1 站厅 | 从站台出发的全部 4 条路线 |
| E2 | B1 站厅 ↔ A 出口街面 | A、P |
| E3 | B1 站厅 ↔ C 出口街面 | B、H |

## 6 种模拟状态

| 状态 ID | 场景 | 对尚未经过相关设施的路线的影响 |
| --- | --- | --- |
| `normal` | 设施正常 | 按模拟连接提供路线 |
| `e2` | E2 电梯停运 | A、P 受阻；商场行程可在站厅改走 B |
| `e1` | E1 电梯停运 | 从站台出发的全部路线受阻；已到站厅的剩余路线不受此故障影响 |
| `e3` | E3 电梯停运 | B、H 受阻；商场行程可在站厅改走 A |
| `southClosed` | 商场南入口关闭 | A 受阻；从站台或站厅出发可改走 B |
| `rain` | 公园通道积水 | P 的公园通道不可用；不代表实时天气，也不影响其他目的地 |

可用性按“已确认位置之后还需经过的设施”判断。已到 A 出口街面时，E2 停运不会要求折返；已到 C 出口街面时，E3 停运也不会阻断后续入口路径。

替代路线必须保留原目的地。目前只有商场提供 A/B 两条路线；医院 H 与公园 P 受阻时提供协助提示，不会改成去商场。数据没有提供 A、C 两个街面出口之间的连接，因此不会从 A 出口街面凭空切换到 C 出口路线。模拟状态开关只影响模拟路线，不修改真实站点资料。

## 后续接入真实路线

`window.ACCESS_DATA` 提供模拟路线与规则，`window.ACCESS_REAL` 提供独立的官方设施摘要。真实试点应建立单独的数据适配层，保留合成样例用于回归验证。

1. **补全路径段。** 为地点、楼层、设施及连接使用稳定 ID，记录起终点、方向、通行条件和适用需求；不能从设施清单直接推导完整路线。
2. **分开保存属性与状态。** 服务楼层与位置属于设施属性；停运、封闭与积水属于状态事件。为状态保存来源、确认时间、有效期及未知/待复核状态。
3. **保留不同日期的含义。** 区分检索时间、来源更新时间和现场核验时间，替换虚构尺寸、距离、照片与核验记录后再进入真实使用。
4. **按确认位置改道。** 保存位置来源与不确定性；只允许沿已知连接前进，并保留用户原本选择的目的地。
5. **建立反馈处理流程。** 若接入真实提交，补充服务端接收、处理状态、权限控制与必要的个人信息保护；当前本地反馈没有通知或响应能力。

真实路线进入使用前，还需现场核验，并邀请轮椅使用者共同检查地标辨认、通行条件和交互负担。
